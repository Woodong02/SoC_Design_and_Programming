# TDMA IP — 데이터링크 계층 설계 결정

> 버전: 0.1
> 작성일: 2026-05-18

---

## 1. 프레이밍 (Framing)

### 1.1 프레임 길이 방식

**결정**: 고정 길이 프레임. 종료 신호 필드 없음.

**근거**: 송수신 양쪽이 필드 폭을 사전에 알고 있으므로 수신기는 비트 수만 카운팅하면 된다. 가변 길이 대비 상태 머신이 단순하고 Verilog 구현이 쉽다.

### 1.2 프레임 시작 감지

**결정**: SFD(Start Frame Delimiter) 없음. 비트 카운팅 방식.

**근거**: Manchester 인코딩에서 preamble(0x55)의 규칙적인 파형으로 비트 타이밍을 복원한 뒤 비트를 카운팅한다. 오류는 CRC가 검출하므로 SFD가 없어도 충분하다. SFD를 추가하면 상태 머신에 단계가 하나 늘어나 복잡도가 증가한다.

### 1.3 비트 순서

**결정**: MSB first.

**근거**: Verilog 시프트 레지스터의 자연스러운 방향(`{reg[N-2:0], new_bit}`)이며, CRC-16 CCITT 표준과 일치한다.

## 2. 프레임 구조

### 2.1 슬레이브 프레임 (슬레이브 → 마스터, RX 케이블)

```
[preamble 8b][addr 3b][payload 32b][TX_TICK 32b][CRC-16 16b]
 ←────────────────── 91비트 ──────────────────────────────→
              └──────── CRC 커버 범위 ────────────────────┘
```

| 필드 | 폭 | 설명 |
|------|----|------|
| preamble | 8비트 | 0x55 고정. Manchester 클럭 복원용 |
| addr | 3비트 | 슬레이브 주소 (0~7). 마스터가 슬롯 검증에 사용 |
| payload | 32비트 | 슬레이브 센서 데이터 |
| TX_TICK | 32비트 | 슬레이브 로컬 카운터 타임스탬프 |
| CRC-16 | 16비트 | addr + payload + TX_TICK에 대한 CRC |

### 2.2 마스터 브로드캐스트 프레임 (마스터 → 슬레이브, TX 케이블)

```
[preamble 8b][TX_TICK 32b][CRC-16 16b]
 ←────────────── 56비트 ─────────────→
              └── CRC 커버 범위 ──────┘
```

| 필드 | 폭 | 설명 |
|------|----|------|
| preamble | 8비트 | 0x55 고정 |
| TX_TICK | 32비트 | 마스터 로컬 카운터 타임스탬프 |
| CRC-16 | 16비트 | TX_TICK에 대한 CRC |

**근거**: 마스터 프레임은 틱 배포만을 목적으로 하므로 슬레이브 프레임과 구조를 같게 할 이유가 없다. 목적에 맞는 최소한의 구조로 정의한다. TX 케이블이 마스터 전용이므로 별도 타입 식별자 없이 방향으로 구분된다.

## 3. 오류 검출

**결정**: CRC-16 CCITT (다항식 0x1021).

**근거**: 64비트(payload + TX_TICK) 데이터에 대해 CRC-8은 검출 능력이 부족하고 CRC-32는 과도하다. CRC-16은 16비트 이하 버스트 오류 및 단일·이중 비트 오류를 모두 검출할 수 있어 적합하다. 다항식과 폭 모두 Verilog 레퍼런스 구현이 풍부하다.

CRC 폭 자체는 Verilog 구현 난이도에 실질적인 차이를 주지 않는다 (LFSR 구조 동일, 폭만 다름).

## 4. 슬롯 내 재전송

**결정**:
- 재전송은 동일 슬롯 내에서 수행한다.
- 프레임 간 IFG(Inter-Frame Gap) 2비트(idle High)를 둔다.
- 재전송 시 TX_TICK 값을 첫 전송 값 그대로 유지한다.
- 재전송 횟수는 RETRY_CNT 레지스터로 설정한다.

**슬롯 내 구조**:
```
[프레임][IFG 2b][프레임][IFG 2b] ... [프레임][guard time]
 ←────────────── RETRY_CNT+1 회 ──────────────→
```

**IFG 근거**: 간격 없이 연속 전송하면 마스터 RX 엔진의 CRC 검사 완료와 다음 preamble 시작이 겹칠 수 있다. 2비트 idle로 RX 엔진이 상태를 리셋할 여유를 보장한다.

**TX_TICK 고정 근거**: 재전송은 동일 전송 시도의 반복이다. 틱 값이 바뀌면 마스터가 수신한 타임스탬프의 일관성이 깨진다.

## 5. MAC 부계층

### 5.1 슬롯 길이 자동 계산

슬롯 길이를 사용자가 직접 설정하지 않고 하드웨어가 자동 계산한다. 설정 실수로 인한 슬롯 충돌을 구조적으로 방지한다.

```
frame_ticks = 91 × 2 × (DIV + 1)
IFG_ticks   = 2  × 2 × (DIV + 1)

slot_ticks  = (RETRY_CNT + 1) × frame_ticks
            + RETRY_CNT × IFG_ticks
            + GUARD_TICKS
```

계산 결과는 **SLOT_TICKS_RO** (읽기 전용 레지스터)로 노출하여 사용자가 검증할 수 있도록 한다.

### 5.2 Guard Time

**GUARD_TICKS**: 사용자 설정 (RW).

**GUARD_MIN_RO**: 하드웨어 계산 최솟값 (읽기 전용). 사용자가 GUARD_TICKS를 이 값보다 작게 설정하지 않도록 참조 기준을 제공한다.

```
GUARD_MIN = RX_PROCESS_CYCLES + CABLE_DELAY_TICKS + MARGIN
```

케이블 지연은 Verilog 파라미터로부터 계산된다:

```verilog
parameter CABLE_LENGTH_CM   = 50;
parameter CABLE_DELAY_NS    = (CABLE_LENGTH_CM * 5 + 99) / 100; // 5ns/m, 올림
parameter CLK_PERIOD_NS     = 40;                                // 25MHz
parameter CABLE_DELAY_TICKS = (CABLE_DELAY_NS + CLK_PERIOD_NS - 1) / CLK_PERIOD_NS;
// 50cm → 0 ticks (25MHz 기준 전파 지연 < 1클럭)
```

케이블 길이 변경 시 파라미터 하나만 수정하면 GUARD_MIN이 자동으로 반영된다.

### 5.3 슬레이브 슬롯 시작 감지

**기준점**: 마스터 브로드캐스트의 첫 번째 falling edge (idle High → Low).

```
RX 라인: ─────┐
               └─ ...  ← 이 에지가 사이클 시작 기준
```

슬레이브는 이 에지를 감지한 순간부터 로컬 클럭으로 카운팅을 시작한다.

```
슬롯 시작까지 대기 = SLAVE_ADDR × slot_ticks
```

preamble 수신 및 CRC 검증은 슬롯 카운터와 **병렬**로 진행된다. 검증 결과가 타이밍을 막지 않는다.

| SLAVE_ADDR | 동작 |
|------------|------|
| 0 | 에지 감지 즉시 송신 시작 (마스터 브로드캐스트와 동시, 이중 케이블로 충돌 없음) |
| n | 에지로부터 n × slot_ticks 후 송신 시작 |

**브로드캐스트 미수신 시**: 예상 사이클 주기 내에 falling edge가 감지되지 않으면 해당 사이클을 스킵하고 SYNC_ERR 플래그를 설정한다. 다음 브로드캐스트를 기다린다.

### 5.4 결함 슬레이브 슬롯 처리

**결정**: fault 상태 슬레이브의 슬롯을 사이클에서 제거하지 않는다. 사이클 주기는 NODE_CNT 기준으로 항상 고정이다.

**근거**: 슬롯을 제거하면 사이클 주기가 가변적이 되어 다른 슬레이브의 타이밍이 흔들린다. 마스터는 fault 슬롯에서 RX 윈도우를 열되, 아무것도 수신하지 않으면 그대로 흘려보낸다. 슬롯이 유지되어야 fault 슬레이브의 복구 감지도 가능하다.

### 5.5 초기 기동

| 노드 | 동작 |
|------|------|
| 마스터 | ENABLE 시 즉시 사이클 0 시작, 첫 브로드캐스트 송신 |
| 슬레이브 | 전원 인가 후 RX 라인 모니터링 대기 → 첫 falling edge 감지 시 자동 동기 획득 |

별도 핸드셰이크 없이 자연스럽게 동기가 성립한다.
