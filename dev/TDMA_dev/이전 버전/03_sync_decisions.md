# TDMA IP — 동기화 메커니즘 설계 결정

> 버전: 0.1
> 작성일: 2026-05-18

---

## 1. 기본 구조

마스터는 자신의 로컬 카운터를 기준으로 자유 진행한다. 슬레이브가 마스터 기준에 맞춰 보정한다.

```
마스터: raw_counter (자유 진행, 보정 없음)
슬레이브: raw_counter + TICK_OFFSET (보정된 시간을 TX_TICK으로 전송)
```

---

## 2. 틱 비교 및 드리프트 계산

매 사이클, 마스터와 슬레이브가 각자 독립적으로 오프셋과 드리프트를 계산한다.

**슬레이브 측:**
```
D[k]     = RX_TICK[k] - TX_TICK[k]
drift[k] = D[k] - D[k-1]
```

**마스터 측 (슬레이브 n에 대해):**
```
D[n][k]     = NODE_TICK[n][k] - TX_TICK[k]
drift[n][k] = D[n][k] - D[n][k-1]
```

두 계산은 같은 물리적 클럭 차이를 각자의 데이터로 독립 측정한다. DRIFT_TH를 공유하거나 맞출 필요가 없다.

---

## 3. 슬레이브 보정

**방식**: 매 사이클 전량 보정. 하드웨어가 자동 적용. 별도 활성화 없음.

```
guard time 진입 시:
    TICK_OFFSET -= drift[k]
```

크리스탈 드리프트는 안정적인 환경에서 사실상 상수이므로, 전량 보정 1회로 수렴하고 이후 안정 상태를 유지한다. 오버슈트 발생 조건이 없다.

보정은 슬레이브 자신의 슬롯 종료 후 guard time에 적용된다. 이 시점은 TX_TICK 캡처가 완료된 후이므로 당 사이클 타임스탬프에 영향을 주지 않는다.

---

## 4. Fault 체계

동기화 관련 fault는 두 종류로 분리한다.

### 4.1 SYNC_FAULT — 드리프트 속도 이상

| 항목 | 내용 |
|------|------|
| 감지 조건 | `\|drift[k]\| > DRIFT_TH` |
| 의미 | 사이클 간 드리프트 변화량이 허용 범위 초과. 일시적 이상. |
| 감지 주체 | 마스터·슬레이브 각자 독립 감지 |
| 회복 가능성 | 가능. 보정 후 자동 복구. |

**슬레이브 동작:**
```
SYNC_FAULT 감지
    → 현재 사이클 전송 중단
    → 다음 1사이클 동안 마스터 틱 수신 및 TICK_OFFSET 보정
    → 그 다음 사이클부터 전송 재개
```

슬레이브가 자율적으로 1사이클 멈추는 이유: 재개 시점에 TICK_OFFSET 보정이 완료되어 슬롯 타이밍 침범 위험을 제거하기 위함이다.

**마스터 동작:**
```
SYNC_FAULT 감지
    → 해당 슬롯을 fault 상태로 마킹
    → 슬레이브가 재개한 뒤 RECOVERY_TH 사이클 연속으로 drift 정상 확인
    → 정상 복구 선언
```

슬롯은 fault 상태에서도 사이클에서 제거되지 않는다. 마스터는 RX 윈도우를 유지하며 복구를 감시한다.

### 4.2 CLOCK_FAULT — 누적 오프셋 이상

| 항목 | 내용 |
|------|------|
| 감지 조건 | `\|D[k]\| > OFFSET_TH` |
| 의미 | 누적 오프셋이 보정 가능 범위를 초과. 클럭 근본 불일치. |
| 감지 주체 | **마스터 전용** |
| 회복 가능성 | 자동 복구 없음. 수동 개입(PS 리셋) 필요. |

**마스터 동작:**
```
CLOCK_FAULT 감지
    → 해당 슬레이브를 TDMA 사이클 동안 영구 격리
    → 격리된 슬롯은 빈 슬롯으로 유지 (타이밍 구조 변경 없음)
    → PS가 SOFT_RST 또는 명시적 클리어 전까지 격리 유지
```

슬레이브는 CLOCK_FAULT 선언을 알지 못한다. 슬레이브는 마스터 틱을 계속 수신하고 TICK_OFFSET 보정을 계속 시도하지만, 마스터가 해당 슬롯의 데이터를 수락하지 않는다. 격리 해제는 PS의 명시적 개입으로만 가능하다.

## 5. 전체 상태 전이

### 마스터가 관리하는 슬레이브 n의 상태

```
        ┌─────────────────────────────────────────────┐
        │                  NORMAL                     │
        └──────┬─────────────────────┬────────────────┘
               │                     │
    |drift|>DRIFT_TH           |D[k]|>OFFSET_TH
               │                     │
               ▼                     ▼
        ┌─────────────┐      ┌──────────────────┐
        │ SYNC_FAULT  │      │   CLOCK_FAULT    │
        └──────┬──────┘      │  (영구 격리)     │
               │             └──────────────────┘
   RECOVERY_TH 사이클              PS 리셋만
   연속 정상                       복구 가능
               │
               ▼
        ┌─────────────┐
        │   NORMAL    │
        └─────────────┘
```

### 슬레이브 자신의 상태

```
        ┌──────────────────────────────┐
        │           NORMAL             │
        │  (매 사이클 TICK_OFFSET 보정) │
        └──────────┬───────────────────┘
                   │
          |drift|>DRIFT_TH
                   │
                   ▼
        ┌──────────────────────┐
        │   PAUSE (1사이클)    │
        │  전송 중단           │
        │  마스터 틱 수신 + 보정│
        └──────────┬───────────┘
                   │
          다음 사이클 자동 재개
                   │
                   ▼
        ┌──────────────────────┐
        │  TRANSMIT (재개)     │
        │  마스터가 복구 감시  │
        └──────────────────────┘
```

슬레이브는 CLOCK_FAULT를 인지하지 않는다. 마스터가 격리를 선언해도 슬레이브는 계속 동작한다.

---

## 6. 관련 레지스터 (확정 예정)

| 레지스터 | 위치 | 설명 |
|---------|------|------|
| DRIFT_TH | 마스터, 슬레이브 각각 | 드리프트 속도 임계값 |
| OFFSET_TH | 마스터 | 누적 오프셋 임계값 (CLOCK_FAULT용) |
| RECOVERY_TH | 마스터 | SYNC_FAULT 복구 확인 사이클 수 |
| TICK_OFFSET | 슬레이브 | 보정 오프셋 (하드웨어 자동 갱신, PS도 읽기 가능) |
| RX_TICK | 슬레이브 | 수신한 마스터 틱 저장 |
| TX_TICK | 마스터·슬레이브 각각 | 자신이 전송한 틱 저장 |
| NODE_TICK[n] | 마스터 | 슬레이브 n으로부터 수신한 틱 저장 |

세부 주소 및 비트 구성은 레지스터 맵 설계 단계에서 확정한다.
