# TDMA IP — 동기화 메커니즘 설계 결정

> 버전: 0.3
> 작성일: 2026-05-21

---

## 1. 기본 구조

마스터는 자신의 로컬 카운터를 기준으로 자유 진행한다. 슬레이브가 마스터 기준에 맞춰 보정한다.

```
마스터: raw_counter (자유 진행, 보정 없음)
슬레이브: raw_counter + TICK_OFFSET (보정된 시간을 TX_TICK으로 전송)
```

동기화 메커니즘은 TX 케이블(마스터 브로드캐스트)과 공유 RX 버스(슬레이브 응답)를 통해 이루어진다. 버스 구조의 변화는 동기화 로직 자체에는 영향을 주지 않는다.

각 노드는 동일 생산 공정의 별도 크리스탈 소스를 사용한다. 공칭 주파수는 동일하나 제조 오차로 인해 미세한 주파수 편차가 존재하며, offset[k]는 사실상 상수에 가깝지만 0이 아닐 수 있다. 보정 로직은 이 편차를 추적·보정하기 위해 의미를 갖는다.

## 2. 틱 교환 및 오프셋 계산

마스터와 슬레이브는 매 사이클 자신의 틱을 상대에게 전송한다. 각자는 수신한 틱과 자신이 보낸 틱의 차이 D를 계산한다. 두 클럭 속도가 일치한다면 D는 사이클 간에 일정한 고정값이다. D의 사이클 간 변화량을 **오프셋(offset)**으로 정의한다.

**슬레이브 측:**
```
D[k]      = RX_TICK[k] - SLV_TX_TICK[k]   (수신한 마스터 틱 - 슬레이브 자신이 보낸 틱)
offset[k] = D[k] - D[k-1]                 (D의 변화량 = 클럭 오프셋)
```

> `RX_TICK`: 슬레이브가 수신한 마스터의 TX_TICK (TX 케이블 경유)
> `SLV_TX_TICK`: 슬레이브 자신이 해당 사이클에 전송한 TX_TICK (raw_counter + TICK_OFFSET)

**마스터 측 (슬레이브 n에 대해):**
```
D[n][k]       = NODE_TICK[n][k] - MST_TX_TICK[k]
offset[n][k]  = D[n][k] - D[n][k-1]
```

> `NODE_TICK[n]`: 마스터가 공유 RX 버스에서 슬레이브 n의 슬롯으로부터 수신한 TX_TICK
> `MST_TX_TICK`: 마스터 자신이 해당 사이클에 전송한 TX_TICK

마스터는 계산한 offset[n][k]를 레지스터로 출력한다(PS에서 관측 가능). 슬레이브는 자신의 offset[k]로 클럭을 보정한다. 두 계산은 같은 물리적 클럭 차이를 각자의 데이터로 독립 측정하므로 별도 동기화가 필요 없다.

**초기 기동 처리**: k=0 사이클에서는 D[k-1]이 없으므로 offset 계산이 불가하다. D_prev 레지스터를 첫 수신값(D[0])으로 초기화하고, k=1 사이클부터 오프셋 계산·보정·fault 판정을 정상 수행한다. k=0에서는 D[0]만 저장하고 보정 및 fault 판정을 스킵한다.

## 3. 슬레이브 보정

**방식**: 매 사이클 전량 보정. 하드웨어가 자동 적용. 별도 활성화 없음.

```
guard time 정 중앙 시점에:
    TICK_OFFSET += offset[k]   // signed 덧셈. offset > 0이면 마스터가 빠름 → TICK_OFFSET 증가로 보정
```

재동기 시점을 guard time 정 중앙으로 고정한다. 이 시점은 슬롯 전송 완료 후 GUARD_TICKS/2 클럭이 경과한 지점이다. 오프셋 측정과 fault 판정이 동일 시점을 기준으로 이루어진다.

크리스탈 드리프트는 안정적인 환경에서 사실상 상수이므로, 전량 보정 1회로 수렴하고 이후 안정 상태를 유지한다. 오버슈트 발생 조건이 없다.

**구현 참고**: guard time 정 중앙 시점은 슬롯 카운터와 별개의 guard time 내부 카운터로 관리한다. 프레임 전송 완료(frame_ticks 경과) 후 GUARD_TICKS/2 카운팅이 완료되는 시점에 보정 및 fault 판정을 수행한다. 마스터의 경우 슬롯 내 frame_ticks 경과 후 동일하게 GUARD_TICKS/2 카운팅하여 동일 시점을 기준으로 삼는다.

## 4. Fault 체계

동기화 관련 fault는 두 종류로 분리한다. 상세 상태 머신 및 복구 절차는 `04_fault_decisions.md` 참조.

### 4.1 SYNC_FAULT — 오프셋 경고 수준 초과

| 항목 | 내용 |
|------|------|
| 감지 조건 | `\|offset[k]\| > GUARD_TICKS / 4` |
| 의미 | 타이밍 오프셋이 guard time의 1/4 초과. 슬롯 경계 침범 위험 경고 수준. 공유 버스에서 슬롯 침범은 다른 슬레이브의 전송을 오염시킨다. |
| 감지 주체 | 마스터·슬레이브 각자 독립 감지 |
| 회복 가능성 | 가능. 보정 후 자동 복구. |

GUARD_TICKS/4를 초과하면 sync_fault 카운터를 증가시킨다. GUARD_TICKS/2 미만이므로 CLOCK_FAULT 조건에는 해당하지 않는다.

**슬레이브 동작:**
```
SYNC_FAULT 감지
    → 현재 사이클 전송 중단 (공유 버스 오염 방지)
    → 다음 1사이클 동안 마스터 틱 수신 및 TICK_OFFSET 보정
    → 그 다음 사이클부터 전송 재개
```

슬레이브가 자율적으로 1사이클 멈추는 이유: 재개 시점에 TICK_OFFSET 보정이 완료되어 슬롯 타이밍 침범 위험을 제거하기 위함이다. 공유 버스에서 슬롯 침범은 다른 슬레이브 데이터를 직접 손상시키므로 이 조치가 필수적이다.

**마스터 동작:**
```
SYNC_FAULT 감지
    → SYNC_FAULT_CNT 증가
    → SYNC_FAULT_CNT >= SYNC_FAULT_TH 시 해당 슬롯을 SYNC_FAULT 상태로 마킹
    → 슬레이브 재개 후 SYNC_RECOVERY_TH 사이클 연속 |offset| <= GUARD_TICKS/4 확인
    → 정상 복구 선언
```

슬롯은 fault 상태에서도 사이클에서 제거되지 않는다. 공유 버스에서 슬롯 구조를 변경하면 전 슬레이브의 타이밍이 흔들리기 때문이다.

### 4.2 CLOCK_FAULT — 오프셋 한계 초과

| 항목 | 내용 |
|------|------|
| 감지 조건 | `\|offset[k]\| > GUARD_TICKS / 2` |
| 의미 | 오프셋이 guard time의 절반 초과. 슬롯 경계를 침범할 수준. 공유 버스에서 즉각 격리가 필요. |
| 감지 주체 | **마스터 전용** |
| 회복 가능성 | 자동 복구 없음. 수동 개입(PS 리셋) 필요. |

GUARD_TICKS/2를 초과하면 보정 계산 전에 즉시 CLOCK_FAULT로 처리한다. 이 임계값은 별도 레지스터 없이 GUARD_TICKS로부터 하드와이어드로 계산된다.

CLOCK_FAULT 조건은 반드시 SYNC_FAULT 조건도 만족한다. 이 경우 SYNC_FAULT_CNT를 먼저 증가시킨 후 CLOCK_FAULT로 즉시 전환한다. CLOCK_FAULT 복구(PS 리셋) 시 SYNC_FAULT_CNT도 함께 초기화한다.

**마스터 동작:**
```
CLOCK_FAULT 감지
    → 해당 슬레이브를 TDMA 사이클 동안 영구 격리
    → HW가 HALT_CMD 비트맵에서 해당 슬레이브 비트를 자동으로 1로 세팅
      (공유 버스 오염 방지를 위한 즉각 중단)
    → 격리된 슬롯은 빈 슬롯으로 유지 (타이밍 구조 변경 없음)
    → PS가 SOFT_RST 또는 명시적 클리어 전까지 격리 유지
    → SOFT_RST 시 SYNC_FAULT_CNT도 함께 초기화
```

슬레이브는 CLOCK_FAULT 선언을 직접 인지하지 못한다. 그러나 HALT_CMD 비트를 수신하면 즉시 전송을 중단하여 공유 버스를 해제한다.

## 5. 동기화 관련 상태 다이어그램

### 마스터가 관리하는 슬레이브 n의 동기화 상태

```
        ┌──────────────────────────────────────────────────┐
        │                    NORMAL                        │
        └──────────┬───────────────────────┬───────────────┘
                   │                       │
   |offset[n]|>GUARD_TICKS/4        |offset[n]|>GUARD_TICKS/2
   → SYNC_FAULT_CNT++               → SYNC_FAULT_CNT++ 후
   SYNC_FAULT_CNT>=SYNC_FAULT_TH      즉시 CLOCK_FAULT 처리
                   │                       │
                   ▼                       ▼
          ┌──────────────┐       ┌──────────────────┐
          │  SYNC_FAULT  │       │   CLOCK_FAULT    │
          └──────┬───────┘       │  (영구 격리,     │
                 │               │  HALT_CMD 자동)  │
  SYNC_RECOVERY_TH 사이클        └──────────────────┘
  연속 |offset|<=GUARD_TICKS/4        PS 리셋만
                 │                    복구 가능
                 ▼                 (리셋 시 CNT 초기화)
          ┌──────────────┐
          │    NORMAL    │
          └──────────────┘
```

DATA_FAULT, LINE_FAULT 등 전체 상태 머신은 `04_fault_decisions.md` §4 참조.

### 슬레이브 동기화 관련 상태 (PAUSE)

```
        ┌──────────────────────────────────────────────────┐
        │                  NORMAL                          │
        │  (guard time 정 중앙: TICK_OFFSET -= offset[k]) │
        └────────────┬─────────────────────────────────────┘
                     │
         |offset[k]| > GUARD_TICKS/4
                     │
                     ▼
          ┌──────────────────────┐
          │   PAUSE (1사이클)    │
          │  전송 중단           │
          │  마스터 틱 수신 + 보정│
          └──────────┬───────────┘
                     │
           다음 사이클 자동 재개
                     ▼
          ┌──────────────────────┐
          │        NORMAL        │
          └──────────────────────┘
```

슬레이브의 전체 상태 머신(FAULT, DEAD, HALT_CMD 포함)은 `04_fault_decisions.md` §5 참조.

## 6. 관련 레지스터 (확정 예정)

| 레지스터 | 위치 | 설명 |
|---------|------|------|
| GUARD_TICKS | 마스터, 슬레이브 | guard time 길이. SYNC_FAULT(÷4)·CLOCK_FAULT(÷2) 임계값의 기준. 4의 배수 미만 시 하위 비트 내림 처리됨 |
| SYNC_FAULT_TH | 마스터 | SYNC_FAULT_CNT 임계값 |
| SYNC_RECOVERY_TH | 마스터 | sync fault 복구 연속 성공 횟수 |
| TICK_OFFSET | 슬레이브 | 보정 오프셋. **signed 32비트**. guard time 정 중앙에 `+= offset[k]` 자동 적용. PS도 읽기/쓰기 가능 |
| RX_TICK | 슬레이브 | 수신한 마스터 틱 저장 (= RX_TICK[k], TX 케이블 경유) |
| TX_TICK | 마스터·슬레이브 각각 | 자신이 전송한 틱 저장 (SLV_TX_TICK 또는 MST_TX_TICK) |
| NODE_TICK[n] | 마스터 | 공유 RX 버스에서 슬레이브 n의 슬롯으로부터 수신한 틱 |

`DRIFT_TH`와 `OFFSET_TH`는 제거한다. 오프셋 임계값은 `GUARD_TICKS` 기반으로 하드와이어드 계산되므로 별도 레지스터가 불필요하다.

세부 주소 및 비트 구성은 레지스터 맵 설계 단계에서 확정한다.
