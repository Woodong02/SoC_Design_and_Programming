# TDMA IP — 데이터링크 계층 설계 결정

> 버전: 0.4
> 작성일: 2026-05-21
> v0.4 변경: TX_TICK 필드 제거. 프레임 50비트로 재설계. Hamming 7비트(6+1)로 변경.

---

## 1. 프레이밍 (Framing)

### 1.1 프레임 길이 방식

**결정**: 고정 길이 프레임. 종료 신호 필드 없음.

**근거**: 송수신 양쪽이 필드 폭을 사전에 알고 있으므로 수신기는 비트 수만 카운팅하면 된다. 가변 길이 대비 상태 머신이 단순하고 Verilog 구현이 쉽다.

### 1.2 프레임 시작 감지

**결정**: 각 슬롯별 슬레이브가 송신하는 preamble bit 0xAA의 첫 비트 1을 감지하는 순간 마스터는 비트 샘플링 시작. 

**근거**: 비트의 길이는 정의되어 있으므로 DIV>>2를 이용하여 샘플링. offset drift가 존재해도 guardtime 이내면 프레임 단위로 클럭 동기화 기능 가능.

### 1.3 비트 순서

**결정**: MSB first.

**근거**: Verilog 시프트 레지스터의 자연스러운 방향(`{reg[N-2:0], new_bit}`)이며, Hamming 비트 위치 계산과도 일관성을 유지한다.

## 2. 프레임 구조

### 2.1 슬레이브 프레임 (슬레이브 → 마스터, 공유 RX 버스)

```
[preamble 8b][addr 3b][payload 32b][Hamming 7b]
 ←────────────────── 50비트 ───────────────────→
              └── Hamming 커버 범위 (35비트) ──┘
```

| 필드 | 폭 | 설명 |
|------|-----|------|
| preamble | 8비트 | 0xAA 고정. NRZ 클럭 복원용. Hamming 커버 범위 밖 |
| addr | 3비트 | 슬레이브 주소 (0~7). 공유 버스에서 마스터가 송신 슬레이브를 식별하고 슬롯 번호와 대조하여 침범을 감지 |
| payload | 32비트 | 슬레이브 센서 데이터 |
| Hamming | 7비트 | SEC-DED. addr + payload (35비트) 커버 |

### 2.2 마스터 브로드캐스트 프레임 (마스터 → 슬레이브, TX 케이블)

```
[preamble 8b][HALT_CMD 8b][reserved 27b][Hamming 7b]
 ←────────────────────── 50비트 ─────────────────────→
              └────────── Hamming 커버 범위 (35비트) ──┘
```

| 필드 | 폭 | 설명 |
|------|----|------|
| preamble | 8비트 | 0x55 고정. Manchester 클럭 복원용. Hamming 커버 범위 밖 |
| HALT_CMD | 8비트 | 슬레이브 중단 명령 비트맵. bit n=1이면 슬레이브 n에 작업 중단 명령 |
| reserved | 27비트 | 향후 사용 예약. 0으로 전송. 슬레이브 프레임과 총 길이 통일을 위한 패딩 |
| Hamming | 7비트 | SEC-DED. HALT_CMD + reserved (35비트) 커버 |

**근거**:
- 슬레이브 프레임(50비트)과 총 길이를 통일한다. Hamming 커버 대상이 동일(35비트)하므로 마스터·슬레이브가 동일한 Hamming 인코더/디코더 로직을 공유한다.
- HALT_CMD는 마스터 HW가 고장 슬레이브에게 중단 명령을 내리는 수단으로, 공유 버스에서 비정상 슬레이브가 버스를 오염시키는 것을 방지한다.
- TX_TICK 필드를 제거하여 프레임을 83비트에서 50비트로 단축한다. 슬롯이 짧아져 실질 처리량이 향상되며, 클럭 동기 로직이 불필요해져 구현이 단순해진다.

## 3. 오류 검출 및 정정

**결정**: SEC-DED Hamming 코드 (7 패리티 비트 = 6 패리티 + 1 전체 패리티).

### 3.1 패리티 비트 수 산출

35비트 데이터에 대한 단일 비트 오류 정정(SEC)에 필요한 패리티 비트 r:

```
조건: 2^r ≥ 35 + r + 1
r = 5 → 32 ≥ 41 ? 불만족
r = 6 → 64 ≥ 42 ? 만족 ✓
```

따라서 6비트 패리티로 SEC 구현, + 전체 패리티 1비트로 DED 추가 → 총 **7비트** Hamming 필드.

### 3.2 Hamming 코드워드 구성

```
35 데이터 비트 + 6 패리티 비트 = 41비트 코드워드
패리티 위치: 1, 2, 4, 8, 16, 32번 위치 (2의 거듭제곱)
나머지 35 위치(3,5,6,7,...,41): 데이터 비트 배치 (MSB first)
전체 패리티: 41비트 전체 XOR
```

Verilog 구현 참고:
- 인코더: 35비트 데이터를 코드워드 위치에 배치 → 각 패리티 비트 계산 (XOR 트리)
- 디코더: 수신 41비트로 신드롬 계산 → 오류 위치 특정 → 1비트 정정 또는 2비트 오류 검출
- 41비트 코드워드 전체가 짧으므로 조합 논리만으로 구현 가능 (레지스터 불필요)

### 3.3 오류 처리

| 오류 종류 | 처리 |
|---------|------|
| 1비트 오류 | 하드웨어 자동 정정 후 정상 수신으로 처리. FAULT_CNT 증가 없음 |
| 2비트 오류 | 검출만 가능, 정정 불가 → `HAMMING_ERR` 플래그 세팅, FAULT_CNT 증가, 프레임 폐기 |
| 3비트 이상 | Hamming SEC-DED 범위 초과. 오검출 또는 오정정 가능성 있음. 단거리 저속 환경에서 발생 확률 무시 가능 |

## 4. MAC 부계층

### 4.1 슬롯 길이 자동 계산

슬롯 길이를 사용자가 직접 설정하지 않고 하드웨어가 자동 계산한다. 설정 실수로 인한 슬롯 충돌을 구조적으로 방지한다.

```
frame_ticks = 50 × 2 × (DIV + 1)

slot_ticks  = frame_ticks + GUARD_TICKS
```

계산 결과는 **SLOT_TICKS_RO** (읽기 전용 레지스터)로 노출하여 사용자가 검증할 수 있도록 한다.

### 4.2 Guard Time

**GUARD_TICKS**: 사용자 설정 (RW).

**GUARD_MIN_RO**: 하드웨어 계산 최솟값 (읽기 전용). 사용자가 GUARD_TICKS를 이 값보다 작게 설정하지 않도록 참조 기준을 제공한다.

```
GUARD_MIN = RX_PROCESS_CYCLES + CABLE_DELAY_TICKS + BUS_TURNAROUND + DRIFT_MARGIN
```

| 항목 | 설명 |
|------|------|
| RX_PROCESS_CYCLES | Manchester 디코딩 + Hamming 검증 완료까지 소요 클럭 |
| CABLE_DELAY_TICKS | 케이블 전파 지연 (왕복). 50cm/5ns·m → 1클럭 미만 → 0 ticks (25MHz 기준) |
| BUS_TURNAROUND | 공유 버스에서 이전 슬레이브의 High-Z 전환 후 다음 슬레이브 구동까지 버스 안정화 여유 |
| DRIFT_MARGIN | 크리스탈 편차 누적 흡수 여유. 상세 산출: `03_sync_decisions(4).md` §2 참조 |

케이블 길이 변경 시 Verilog 파라미터 하나만 수정하면 GUARD_MIN이 자동 반영된다.

```verilog
parameter CABLE_LENGTH_CM   = 50;
parameter CABLE_DELAY_NS    = (CABLE_LENGTH_CM * 5 + 99) / 100;
parameter CLK_PERIOD_NS     = 40;                                // 25MHz
parameter CABLE_DELAY_TICKS = (CABLE_DELAY_NS + CLK_PERIOD_NS - 1) / CLK_PERIOD_NS;
parameter MAX_PPM           = 50;                                // 크리스탈 최대 편차
parameter NODE_CNT_MAX      = 8;
// DRIFT_MARGIN은 slot_ticks 확정 후 계산 (03 문서 참조)
```

공유 버스에서 guard time은 이전 슬레이브의 드라이버가 High-Z로 전환되고 다음 슬레이브의 드라이버가 버스를 구동하기 전까지의 여유 시간을 포함한다.

### 4.3 슬레이브 슬롯 시작 감지

**기준점**: 마스터 브로드캐스트의 첫 번째 액티브 에지 (High-Z → 드라이버 첫 전이).

```
TX 라인: ┌─────
         └─ neutral state에서 GPIO_in 1'b1 감지시 preamble counting 시작. DIV>>1을 이용하여 최대한 비트의 중앙 위치를 샘플링
```

슬레이브 및 마스터는 이 에지를 감지한 순간부터 로컬 클럭으로 카운팅을 시작한다.

```
슬롯 시작까지 대기 = SLAVE_ADDR × slot_ticks + GUARD_TICKS>>1
```

preamble 수신 및 Hamming 검증은 슬롯 카운터와 **병렬**로 진행된다. 검증 결과가 타이밍을 막지 않는다.

| SLAVE_ADDR | 동작 |
|------------|------|
| 0 | 에지 감지 즉시 송신 시작 (마스터 브로드캐스트와 동시. TX/RX 분리로 충돌 없음) |
| n | 에지로부터 n × slot_ticks 후 송신 시작 |

### 4.4 결함 슬레이브 슬롯 처리

**결정**: fault 상태 슬레이브의 슬롯을 사이클에서 제거하지 않는다. 사이클 주기는 NODE_CNT 기준으로 항상 고정이다.

**근거**: 일정 err_cnt를 넘어선 슬레이브에 대해서 마스터는 SHUTDOWN 메세지를 보내며 슬레이브는 SHUTDOWN 메세지 수신시 모든 송신을 중지하여야 한다. 이는 따로 reset을 하지 않는 한 지속된다.

### 4.5 초기 기동

| 노드 | 동작 |
|------|------|
| 마스터 | ENABLE 시 즉시 사이클 0 시작, 첫 브로드캐스트 송신 |
| 슬레이브 | 전원 인가 후 TX 라인 모니터링 대기 → 첫 액티브 에지 감지 시 자동 동기 획득 |

별도 핸드셰이크 없이 자연스럽게 동기가 성립한다.
