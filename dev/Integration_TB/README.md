# Integration_TB

Slave 및 Master의 소스 파일을 모아 시스템 통합 검증(Integration Test)을 수행하는 저장소입니다.

## 📂 디렉토리 구조

text
├── master/                 # Master 소스 파일 및 단위 테스트벤치(TB)
├── slave/                  # Slave 소스 파일 및 단위 테스트벤치(TB)
├── MASTER_ISSUE.md         # Master 소스 파일 변경 사항 기록
├── tb_integration.v        # 최상위 통합 테스트벤치 (Level 1)
├── tb_master_top.v         # 최상위 통합 테스트벤치 (Level 2)
├── tb_sys_integration.v    # 최상위 통합 테스트벤치 (Level 3)
└── tbfix_n7.v              # 최상위 통합 테스트벤치 (Level 4 - 패치 버전)

* **`/master`**: Master 관련 RTL 소스 코드 및 단위 TB가 포함되어 있습니다.
* **`/slave`**: Slave 관련 RTL 소스 코드 및 단위 TB가 포함되어 있습니다.
* **최상위 디렉토리 (`/`)**: 두 모듈을 함께 연동하여 구동하는 통합 테스트벤치(Integration TB)들이 위치합니다.

## 🏗️ 테스트벤치(TB) 위계 및 검증 범위

통합 테스트벤치는 검증 범위와 목적에 따라 아래와 같은 단계별 위계를 가집니다.

| 파일명 | 검증 대상 및 범위 | 주요 특징 |
| --- | --- | --- |
| **`tb_integration.v`** | Master 통신 IP + Slave 통신 IP | 물리 및 데이터 링크 계층의 1:1 송수신 프로토콜 검증 |
| **`tb_master_top.v`** | Master 전체 최상위 + Slave 통신 IP | Master 컨트롤러 중심의 슬롯 순환 및 제어 기능 검증 |
| **`tb_sys_integration.v`** | Master 전체 최상위 + Slave 전체 최상위 | 다중 슬레이브 버스 환경에서의 전신 시스템 통합 검증 |
| **`tbfix_n7.v`** | Master 전체 최상위 + Slave 전체 최상위 | **3비트 오버플로우 버그 패치 완료** 후 최종 확장 검증 |

## 🐛 주요 디버깅 및 버그 패치 이력 (`tbfix_n7`)

### 문제 점검 (`tb_sys_integration.v`)

* **현상**: 시스템에서 슬레이브 노드 개수를 최대 스펙(7개)으로 설정 시, 슬롯 순환이 멈추거나 정상 동작하지 않는 현상 발생.
* **원인**: Master 내부(`Master_top.v`, `Master_slot.v`)에서 슬레이브 노드 번호를 `0 ~ 7` 범위의 **3비트 폭 데이터**로 처리하고 있었습니다. 그러나 로직 내에서 `NODE_CNT + 1` 연산을 먼저 수행함에 따라 노드 번호가 `1 ~ 8`로 확장되었고, 결과적으로 **3비트 폭(`Max 7`)을 초과하여 오버플로우(Overflow)가 발생**했습니다.

### 수정 조치 (`tbfix_n7.v`)

* 내부 카운터 및 슬롯 제어 관련 내부 와이어/레지스터 폭을 **4비트**로 확장하여 오버플로우 문제를 해결했습니다. (외부 포트 인터페이스 스펙은 유지)
* 최대 7개의 슬레이브 노드가 충돌 없이 TDMA 통신을 완수하는 것을 최종 확인했습니다.
